## ✨ ECLIPSE Fleet Release

`remote-agent-onboarding` v0.2.0 promotes the ECLIPSE workflow from a single remote-agent workstation into a small, named fleet.

The release keeps the v0.1.0 standard: do not call an agent ready from one signal. SSH, GUI, Codex CLI/Desktop, Chrome, Browser/IAB, mobile remote control, VPN, and workspace state remain separate proof surfaces.

## 🧭 v0.1.0 And v0.2.0 Scope

v0.1.0 was the initial public release of the ECLIPSE Codex skill. It shipped the evidence-backed onboarding checklist, bilingual README files, Automations reference material, validation tooling, and public-safe ECLIPSE02 screenshots.

v0.2.0 adds the fleet layer:

- `ECLIPSE01-AURORA`
- `ECLIPSE02-AQUA`
- `ECLIPSE03-ONIZUKA`
- `ECLIPSE04-TACHYON`
- `ECLIPSE05-TEMPEST`
- `ECLIPSE06-ONICADIA`
- `ECLIPSE07-HARINA`

The key v0.2.0 lesson is that the phone-visible Codex Desktop name is not just the Linux hostname. It depends on the remote-control backend registration. A rename is incomplete until the daemon, local enrollment, Desktop restart, and current phone/tablet surface all agree.

## 🛡️ Identity And Clone Guardrails

This release tightens the cloned-VM and auth-migration rules:

- copy only minimal Codex auth material when moving login state between VMs;
- preserve or regenerate the target VM's remote-control identity;
- do not copy installation IDs, environment IDs, server IDs, or stale source `server_name` rows;
- restart the daemon/Desktop pair after identity cleanup;
- verify the current mobile connection list before reporting a rename or clone repair as complete.

This prevents a cloned ECLIPSE VM from appearing as the wrong workstation in Codex mobile.

## 🌐 Per-Agent VPN Isolation

v0.2.0 also documents the per-VM Surfshark OpenVPN pattern that was used during the fleet setup work.

The skill now treats VPN as its own proof surface: service state, tunnel interface, external IP/country, and LAN SSH reachability are reported separately from Codex Desktop readiness.

## 🖼️ Public Evidence

The README now includes a public-safe v0.2.0 fleet screenshot showing the mobile-visible naming contract after the identity refresh.

No private installation IDs, environment IDs, server IDs, IP addresses, VPN credentials, account emails, or passwords are included in the release material.
